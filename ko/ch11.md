<a id="11-low-power-support"></a>
# 11 저전력 지원 (Low Power Support)

<a id="111-power-saving-introduction"></a>
## 11.1 전력 절감 개요 (Power Saving Introduction)

FreeRTOS는 idle task(유휴 task) hook(idle task hook)과 tickless 유휴 모드(tickless Idle mode)를 통해 저전력 모드를 손쉽게 활용할 수 있는 방법을 제공한다.

FreeRTOS가 실행 중인 마이크로컨트롤러의 소비 전력을 줄이기 위해 idle task hook을 사용하여 마이크로컨트롤러를 저전력 상태로 전환하는 방식이 널리 사용된다. 이 방법으로 달성할 수 있는 전력 절감 효과는 tick interrupt(tick 인터럽트)를 처리하기 위해 저전력 상태를 주기적으로 빠져나왔다가 다시 진입해야 한다는 필요성 때문에 제한적이다. 게다가 tick interrupt의 빈도가 너무 높으면(유휴 상태에서 너무 자주 깨어남) 매 틱마다 저전력 상태에 진입하고 빠져나오는 데 소비되는 에너지와 시간이 가장 가벼운 절전 모드를 제외한 모든 모드에서 잠재적인 전력 절감 이득을 상쇄해 버린다.

FreeRTOS는 마이크로컨트롤러가 저전력 소비 상태에 주기적으로 진입하고 빠져나올 수 있도록 지원한다. FreeRTOS의 tickless 유휴 모드는 유휴 기간(실행 가능한 애플리케이션 task(태스크)가 없을 때) 동안 주기적인 tick interrupt를 중지시켜, 인터럽트가 발생하거나 RTOS 커널이 task를 Ready 상태로 전환해야 할 시점이 될 때까지 MCU가 깊은 절전 상태를 유지할 수 있도록 한다. 그런 다음 tick interrupt가 다시 시작될 때 RTOS tick count(누적 tick 값) 값을 보정한다. FreeRTOS tickless 모드의 원리는 MCU가 idle task를 수행 중일 때 MCU를 저전력 모드로 진입시켜 시스템 전력 소비를 줄이는 것이다.

<a id="112-freertos-sleep-modes"></a>
## 11.2 FreeRTOS 슬립 모드 (FreeRTOS Sleep Modes)

FreeRTOS에서는 세 가지 유형의 슬립(sleep) 모드를 지원한다:

1. `eAbortSleep` - 이 모드는 task가 준비 완료되었거나, 문맥 전환이 보류(pend)되었거나, scheduler(스케줄러)가 일시 중단된 상태에서 tick interrupt가 이미 발생하여 보류되었음을 나타낸다. 이는 RTOS에 슬립 모드 진입을 중단(abort)하도록 신호를 보낸다.

2. `eStandardSleep` - 이 모드는 예상 유휴 시간보다 오래 지속되지 않는 슬립 모드로 진입할 수 있도록 한다.

3. `eNoTasksWaitingTimeout` - 이 모드는 타임아웃을 기다리는 task가 없을 때 진입하므로 외부 인터럽트나 리셋에 의해서만 빠져나올 수 있는 슬립 모드로 안전하게 진입할 수 있다.

<a id="113-functions-and-enabling-built-in-tickless-idle-functionality"></a>
## 11.3 내장 틱리스 유휴 기능 활성화 및 함수 (Functions and Enabling Built-in Tickless Idle Functionality)

내장 tickless 유휴 기능은 FreeRTOSConfig.h에서 `configUSE_TICKLESS_IDLE`을 1로 정의하여 활성화한다(이 기능을 지원하는 포트의 경우). FreeRTOSConfig.h에서 `configUSE_TICKLESS_IDLE`을 2로 정의하면 내장 구현이 포함된 포트를 포함하여 모든 FreeRTOS 포트에 대해 사용자 정의 tickless 유휴 기능을 제공할 수 있다.

tickless 유휴 기능이 활성화되면 다음 두 가지 조건이 모두 충족될 때 커널이 `portSUPPRESS_TICKS_AND_SLEEP()` 매크로를 호출한다:

1. 모든 애플리케이션 task가 Blocked 상태이거나 Suspended 상태여서 idle task만이 유일하게 실행 가능한 task인 경우.

2. 커널이 애플리케이션 task를 Blocked 상태에서 전환할 예정 시간까지 최소 n개 이상의 완전한 tick(틱) 주기가 남아 있는 경우(여기서 n은 FreeRTOSConfig.h의 `configEXPECTED_IDLE_TIME_BEFORE_SLEEP` 정의에 의해 설정됨).

### 11.3.3 eTaskConfirmSleepModeStatus 함수 (The eTaskConfirmSleepModeStatus Function)

API인 `eTaskConfirmSleepModeStatus`는 슬립 모드 상태를 반환하여 슬립을 진행해도 괜찮은지, 그리고 무기한 슬립에 들어가도 괜찮은지 확인한다. 이 기능은 `configUSE_TICKLESS_IDLE`이 1로 설정된 경우에만 사용할 수 있다.

<a name="list11.3" title="Listing 11.3 The eTaskConfirmSleepModeStatus API function prototype"></a>
 
```c
eSleepModeStatus eTaskConfirmSleepModeStatus( void );
```
***코드 11.3 (Listing 11.3)*** *eTaskConfirmSleepModeStatus API 함수 원형*

`portSUPPRESS_TICKS_AND_SLEEP()` 내에서 호출된 `eTaskConfirmSleepModeStatus()`가 `eNoTasksWaitingTimeout`을 반환하면 마이크로컨트롤러는 딥 슬립 상태를 무기한 유지할 수 있다. `eTaskConfirmSleepModeStatus()`는 다음 조건들이 참일 때만 `eNoTasksWaitingTimeout`을 반환한다:

+ software timer(소프트웨어 타이머)가 사용되지 않아 scheduler가 향후 특정 시점에 타이머 callback 함수를 실행할 예정이 없는 경우.

+ 모든 애플리케이션 task가 Suspended 상태이거나 `portMAX_DELAY` 타임아웃 값으로 Blocked 상태에 있어 scheduler가 향후 고정된 시점에 task를 Blocked 상태에서 벗어나게 할 예정이 없는 경우.

경쟁 상태를 방지하기 위해 FreeRTOS scheduler는 `portSUPPRESS_TICKS_AND_SLEEP()`이 호출되기 전에 일시 중단되며, `portSUPPRESS_TICKS_AND_SLEEP()` 실행이 완료될 때 다시 재개된다. 이렇게 하면 마이크로컨트롤러가 저전력 상태를 빠져나오는 시점과 `portSUPPRESS_TICKS_AND_SLEEP()`이 실행을 완료하는 시점 사이에 애플리케이션 task가 실행되지 않도록 보장된다. 또한 슬립 모드로 진입해도 괜찮은지 확인하기 위해 `portSUPPRESS_TICKS_AND_SLEEP()` 함수는 타이머가 중지되는 시점과 슬립 모드로 진입하는 시점 사이에 작은 critical section(임계 구역)을 생성해야 한다. `eTaskConfirmSleepModeStatus()`는 바로 이 critical section 내에서 호출되어야 한다.

또한 FreeRTOS는 FreeRTOSConfig.h에 정의된 두 개의 다른 인터페이스 함수를 사용자에게 제공한다. 이 매크로들을 통해 애플리케이션 작성자는 MCU가 저전력 상태로 진입하기 전과 진입한 후에 각각 추가적인 단계를 추가할 수 있다.

## 11.4 portSUPPRESS_TICKS_AND_SLEEP() 매크로 구현 (Implementing portSUPPRESS_TICKS_AND_SLEEP() Macro)

사용 중인 FreeRTOS 포트가 `portSUPPRESS_TICKS_AND_SLEEP()`의 기본 구현을 제공하지 않는 경우, 애플리케이션 작성자는 FreeRTOSConfig.h에 `portSUPPRESS_TICKS_AND_SLEEP()`을 정의하여 자체 구현을 제공할 수 있다. 사용 중인 FreeRTOS 포트가 `portSUPPRESS_TICKS_AND_SLEEP()`의 기본 구현을 제공하는 경우에도 애플리케이션 작성자는 FreeRTOSConfig.h에 `portSUPPRESS_TICKS_AND_SLEEP()`을 정의하여 기본 구현을 오버라이드할 수 있다.

다음 소스 코드는 애플리케이션 작성자가 `portSUPPRESS_TICKS_AND_SLEEP()`을 어떻게 구현할 수 있는지 보여주는 예시이다. 이 예제는 기초적인 형태이며 커널이 유지하는 시간과 실제 달력 시간 사이에 약간의 오차가 발생할 수 있다. 예제에 표시된 함수 호출 중 `vTaskStepTick()`과 `eTaskConfirmSleepModeStatus()`만이 FreeRTOS API의 일부이다. 다른 함수들은 사용 중인 하드웨어에서 제공하는 클록 및 절전 모드에 고유한 것이므로 애플리케이션 작성자가 직접 제공해야 한다.

<a name="list11.6" title="Listing 11.6 An example of a user defined implementation of portSUPPRESS\_TICKS\_AND\_SLEEP()"></a>

```c
/* First define the portSUPPRESS_TICKS_AND_SLEEP() macro.  The parameter is the
   time, in ticks, until the kernel next needs to execute. */

#define portSUPPRESS_TICKS_AND_SLEEP( xIdleTime ) vApplicationSleep( xIdleTime )

/* Define the function that is called by portSUPPRESS_TICKS_AND_SLEEP(). */
void vApplicationSleep( TickType_t xExpectedIdleTime )
{
    unsigned long ulLowPowerTimeBeforeSleep, ulLowPowerTimeAfterSleep;

    eSleepModeStatus eSleepStatus;

    /* Read the current time from a time source that will remain operational
       while the microcontroller is in a low power state. */
    ulLowPowerTimeBeforeSleep = ulGetExternalTime();

    /* Stop the timer that is generating the tick interrupt. */
    prvStopTickInterruptTimer();

    /* Enter a critical section that will not effect interrupts bringing the MCU
       out of sleep mode. */
    disable_interrupts();

    /* Ensure it is still ok to enter the sleep mode. */
    eSleepStatus = eTaskConfirmSleepModeStatus();

    if( eSleepStatus == eAbortSleep )
    {
        /* A task has been moved out of the Blocked state since this macro was
           executed, or a context siwth is being held pending.  Do not enter a
           sleep state.  Restart the tick and exit the critical section. */
        prvStartTickInterruptTimer();
        enable_interrupts();
    }
    else
    {
        if( eSleepStatus == eNoTasksWaitingTimeout )
        {
            /* It is not necessary to configure an interrupt to bring the
               microcontroller out of its low power state at a fixed time in 
               the future. */
            prvSleep();
        }
        else
        {
            /* Configure an interrupt to bring the microcontroller out of its low
               power state at the time the kernel next needs to execute.  The
               interrupt must be generated from a source that remains operational
               when the microcontroller is in a low power state. */
            vSetWakeTimeInterrupt( xExpectedIdleTime );

            /* Enter the low power state. */
            prvSleep();

            /* Determine how long the microcontroller was actually in a low power
               state for, which will be less than xExpectedIdleTime if the
               microcontroller was brought out of low power mode by an interrupt
               other than that configured by the vSetWakeTimeInterrupt() call.
               Note that the scheduler is suspended before
               portSUPPRESS_TICKS_AND_SLEEP() is called, and resumed when
               portSUPPRESS_TICKS_AND_SLEEP() returns.  Therefore no other tasks will
               execute until this function completes. */
            ulLowPowerTimeAfterSleep = ulGetExternalTime();

            /* Correct the kernels tick count to account for the time the
               microcontroller spent in its low power state. */
            vTaskStepTick( ulLowPowerTimeAfterSleep - ulLowPowerTimeBeforeSleep );
        }

        /* Exit the critical section - it might be possible to do this immediately
           after the prvSleep() calls. */
        enable_interrupts();

        /* Restart the timer that is generating the tick interrupt. */
        prvStartTickInterruptTimer();
    }
}
```
***코드 11.6 (Listing 11.6)*** *사용자가 정의한 portSUPPRESS\_TICKS\_AND\_SLEEP() 구현 예*

<a id="115-idle-task-hook-function"></a>
## 11.5 유휴 태스크 훅 함수 (Idle Task Hook Function)

유휴(Idle) task는 선택적으로 애플리케이션 정의 hook(또는 callback) 함수인 유휴 hook(idle hook)을 호출할 수 있다. idle task는 가장 낮은 우선순위로 실행되므로, 이러한 유휴 hook 함수는 실행 가능한 더 높은 우선순위 task가 없을 때만 실행된다. 따라서 유휴 hook 함수는 프로세서를 저전력 상태로 전환하기에 이상적인 장소이며, 수행할 처리가 없을 때마다 자동으로 전력을 절감할 수 있도록 한다. 유휴 hook은 FreeRTOSConfig.h 내에서 `configUSE_IDLE_HOOK`이 1로 설정된 경우에만 호출된다.

<a name="list11.7" title="Listing 11.7 The vApplicationIdleHook API function prototype"></a>

```c
void vApplicationIdleHook( void );
```
***코드 11.7 (Listing 11.7)*** *vApplicationIdleHook API 함수 원형*

유휴 hook은 idle task가 실행되는 동안 반복적으로 호출된다. 유휴 hook 함수가 블록(대기)을 유발할 수 있는 API 함수를 호출하지 않도록 하는 것이 매우 중요하다. 또한 애플리케이션이 `vTaskDelete()` API 함수를 사용하는 경우, 삭제된 task에 RTOS 커널이 할당했던 리소스를 정리하는 책임이 idle task에 있으므로 idle task hook이 주기적으로 반환될 수 있도록 허용해야 한다.
