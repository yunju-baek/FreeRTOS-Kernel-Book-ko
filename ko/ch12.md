# 12 개발자 지원 (Developer Support)

<a id="121-introduction"></a>
## 12.1 개요 (Introduction)

이 장에서는 다음과 같은 방법으로 개발 생산성을 극대화하기 위해 포함된 일련의 기능들을 집중적으로 다룬다:

- 응용 프로그램이 어떻게 동작하는지에 대한 통찰력 제공.
- 최적화 기회 포착.
- 오류 발생 시점에서 즉각 오류 감지(trap).


<a id="122-configassert"></a>
## 12.2 configASSERT()

C 언어에서 매크로 `assert()`는 프로그램이 설정한 *어서션(assertion, 가정/단언)*을 검증하는 데 사용된다. 어서션은 C 표현식으로 작성되며, 표현식의 평가 결과가 거짓(0)이면 어서션이 실패한 것으로 간주된다. 예를 들어 Listing 12.1은 포인터 `pxMyPointer`가 NULL이 아니라는 어서션을 테스트한다.


<a name="list12.1" title="Listing 12.1 Using the standard C assert() macro to check pxMyPointer is not NULL"></a>

```c
/* Test the assertion that pxMyPointer is not NULL */
assert( pxMyPointer != NULL );
```
***Listing 12.1*** *Using the standard C assert() macro to check pxMyPointer is not NULL*

응용 프로그램 개발자는 `assert()` 매크로의 구현을 제공함으로써 어서션이 실패했을 때 수행할 동작을 지정한다.

FreeRTOS를 컴파일하는 모든 컴파일러에서 `assert()`를 사용할 수 있는 것은 아니므로 FreeRTOS 소스 코드는 `assert()`를 직접 호출하지 않는다. 대신 FreeRTOS 소스 코드에는 `FreeRTOSConfig.h`에서 응용 프로그램 개발자가 정의할 수 있으며 표준 C `assert()`와 똑같이 동작하는 `configASSERT()`라는 매크로 호출이 다수 포함되어 있다.

실패한 어서션은 치명적인 오류로 취급해야 한다. 어서션이 실패한 라인을 지나쳐 실행을 계속 진행해서는 안 된다.

> *`configASSERT()`를 사용하면 가장 흔한 오류 원인의 상당수를 즉시 포착하고 식별하여 개발 생산성을 향상시킨다. FreeRTOS 응용 프로그램을 개발하거나 디버깅하는 동안에는 `configASSERT()`를 반드시 정의해 둘 것을 강력히 권장한다.*

`configASSERT()`를 정의하면 런타임 디버깅에 큰 도움이 되지만, 응용 프로그램의 코드 크기가 증가하고 따라서 실행 속도가 느려진다. `configASSERT()`의 정의를 제공하지 않으면 기본 빈 정의가 사용되며 C 전처리기에 의해 모든 `configASSERT()` 호출이 완전히 제거된다.


<a id="1221-example-configassert-definitions"></a>
### 12.2.1 configASSERT() 정의 예시 (Example configASSERT() definitions)

Listing 12.2에 표시된 `configASSERT()` 정의는 응용 프로그램이 디버거의 제어하에 실행 중일 때 유용하다. 어서션이 실패한 라인에서 실행이 중단되므로 디버그 세션이 일시 중지될 때 디버거에 표시되는 라인이 바로 어서션이 실패한 라인이 된다.


<a name="list12.2" title="Listing 12.2 A simple configASSERT() definition useful when executing under the control of a debugger"></a>

```c
/* Disable interrupts so the tick interrupt stops executing, then sit
   in a loop so execution does not move past the line that failed the
   assertion. If the hardware supports a debug break instruction, then the
   debug break instruction can be used in place of the for() loop. */

#define configASSERT( x ) if( ( x ) == 0 ) { taskDISABLE_INTERRUPTS(); for(;;); }
```
***Listing 12.2*** *A simple configASSERT() definition useful when executing under the control of a debugger*

Listing 12.3에 표시된 `configASSERT()` 정의는 응용 프로그램이 디버거 제어 없이 실행될 때 유용하다. 어서션이 실패한 소스 코드 라인을 출력하거나 기록한다. 어서션이 실패한 라인은 소스 파일 이름을 가져오는 표준 C 매크로 `__FILE__`과 소스 파일 내의 라인 번호를 가져오는 표준 C 매크로 `__LINE__`을 사용하여 식별된다.


<a name="list12.3" title="Listing 12.3 A configASSERT() definition that records the source code line that failed an assertion"></a>

```c
/* This function must be defined in a C source file, not the FreeRTOSConfig.h 
   header file. */
void vAssertCalled( const char *pcFile, uint32_t ulLine )
{
    /* Inside this function, pcFile holds the name of the source file that 
       contains the line that detected the error, and ulLine holds the line 
       number in the source file. The pcFile and ulLine values can be printed 
       out, or otherwise recorded, before the following infinite loop is 
       entered. */
    RecordErrorInformationHere( pcFile, ulLine );

    /* Disable interrupts so the tick interrupt stops executing, then sit in a 
       loop so execution does not move past the line that failed the assertion. */
    taskDISABLE_INTERRUPTS();
    for( ;; );
}
/*-----------------------------------------------------------*/

/* These following two lines must be placed in FreeRTOSConfig.h. */
extern void vAssertCalled( const char *pcFile, unsigned long ulLine );
#define configASSERT( x ) if( ( x ) == 0 ) vAssertCalled( __FILE__, __LINE__ )
```
***Listing 12.3*** *A configASSERT() definition that records the source code line that failed an assertion*

<a id="124-debug-related-hook-callback-functions"></a>
## 12.4 디버깅 관련 훅(콜백) 함수 (Debug Related Hook (Callback) Functions)

<a id="1241-malloc-failed-hook"></a>
### 12.4.1 동적 메모리 할당 실패 훅 (Malloc failed hook)

동적 메모리 할당 실패 훅(또는 콜백)은 제3장 '힙 메모리 관리'에서 설명하였다.

메모리 할당 실패 훅을 정의하면 태스크, 큐, 세마포어 또는 이벤트 그룹 생성 시도가 실패했을 때 응용 프로그램 개발자가 즉시 알림을 받을 수 있다.

<a id="1242-stack-overflow-hook"></a>
### 12.4.2 스택 오버플로 훅 (Stack overflow hook)

스택 오버플로 훅에 대한 세부 사항은 제13.3절 '스택 오버플로'에 나와 있다.

스택 오버플로 훅을 정의하면 태스크가 사용한 스택 양이 태스크에 할당된 스택 공간을 초과할 때 응용 프로그램 개발자에게 즉시 통지된다.


<a id="125-viewing-run-time-and-task-state-information"></a>
## 12.5 런타임 및 태스크 상태 정보 확인 (Viewing Run-time and Task State Information)

<a id="1251-task-run-time-statistics"></a>
### 12.5.1 태스크 런타임 통계 (Task Run-Time Statistics)

태스크 런타임 통계는 각 태스크가 할당받은 처리 시간의 양에 대한 정보를 제공한다. 태스크의 *런타임(run time)*은 응용 프로그램이 부팅된 이후 해당 태스크가 Running 상태에 머무른 총 시간이다.

런타임 통계는 프로젝트 개발 단계에서 프로파일링 및 디버깅 보조 도구로 사용하기 위한 것이다. 제공되는 정보는 런타임 통계 클록으로 사용되는 카운터가 오버플로되기 전까지만 유효하다. 런타임 통계를 수집하면 태스크 컨텍스트 스위칭 시간이 증가한다.

바이너리 형태의 런타임 통계 정보를 얻으려면 `uxTaskGetSystemState()` API 함수를 호출한다. 사람이 읽을 수 있는 ASCII 테이블 형태의 런타임 통계 정보를 얻으려면 `vTaskGetRunTimeStatistics()` 도우미 함수를 호출한다.


<a id="1252-the-run-time-statistics-clock"></a>
### 12.5.2 런타임 통계 클록 (The Run-Time Statistics Clock)

런타임 통계는 틱 주기의 일부(분수) 단위까지 측정해야 한다. 따라서 RTOS 틱 카운트는 런타임 통계 클록으로 사용되지 않으며 클록은 응용 프로그램 코드에 의해 별도로 제공된다. 런타임 통계 클록의 주파수는 틱 인터럽트 주파수보다 10배에서 100배 빠르게 설정하는 것이 권장된다. 런타임 통계 클록이 빠를수록 통계가 더 정확해지지만 시간 값이 더 빨리 오버플로된다.

이상적으로 시간 값은 별도의 처리 오버헤드 없이 값을 읽을 수 있는 프리러닝(free-running) 32비트 주변장치 타이머/카운터에 의해 생성되는 것이 좋다. 사용 가능한 주변장치와 클록 속도로 인해 이 기법을 사용할 수 없는 경우, 덜 효율적이지만 대안이 될 수 있는 기법은 다음과 같다:

- 원하는 런타임 통계 클록 주파수로 주기적인 인터럽트를 발생시키도록 주변장치를 구성한 다음, 발생한 인터럽트 횟수 카운트를 런타임 통계 클록으로 사용한다.

  이 방식은 주기적 인터럽트가 런타임 통계 클록 제공만을 목적으로 사용되는 경우 매우 비효율적이다. 그러나 응용 프로그램이 이미 적절한 주파수의 주기적 인터럽트를 사용하고 있다면 기존 인터럽트 서비스 루틴에 발생한 인터럽트 횟수를 세는 카운트를 추가하는 것은 간단하고 효율적이다.

- 프리러닝 16비트 주변장치 타이머의 현재 값을 32비트 값의 하위 16비트로 사용하고 타이머가 오버플로된 횟수를 32비트 값의 상위 16비트로 사용하여 32비트 값을 생성한다.

적절하고 다소 복잡한 처리를 거치면 RTOS 틱 카운트와 ARM Cortex-M SysTick 타이머의 현재 값을 결합하여 런타임 통계 클록을 생성할 수도 있다. FreeRTOS 다운로드에 포함된 일부 데모 프로젝트에서 이를 구현하는 방법을 보여준다.


<a id="1253-configuring-an-application-to-collect-run-time-statistics"></a>
### 12.5.3 런타임 통계 수집을 위한 응용 프로그램 설정 (Configuring an Application to Collect Run-Time Statistics)

아래에는 태스크 런타임 통계를 수집하는 데 필요한 매크로들에 대한 세부 정보가 나와 있다. 원래 이 매크로들은 RTOS 포트 레이어에 포함되도록 의도되었기 때문에 'port' 접두사가 붙어 있지만, `FreeRTOSConfig.h`에 정의하는 것이 더 실용적인 것으로 입증되었다.

**런타임 통계 수집에 사용되는 매크로**

- `configGENERATE_RUN_TIME_STATS`

  이 매크로는 FreeRTOSConfig.h에서 1로 설정되어야 한다. 이 매크로가 1로 설정되면 스케줄러가 적절한 시점에 이 절에 설명된 다른 매크로들을 호출한다.

- `portCONFIGURE_TIMER_FOR_RUN_TIME_STATS()`

  이 매크로는 런타임 통계 클록을 제공하는 데 사용되는 주변장치를 초기화하도록 제공되어야 한다.

- `portGET_RUN_TIME_COUNTER_VALUE()` 또는 `portALT_GET_RUN_TIME_COUNTER_VALUE(Time)`

  이 두 매크로 중 하나가 현재 런타임 통계 클록 값을 반환하도록 제공되어야 한다. 이는 응용 프로그램이 처음 부팅된 이후 런타임 통계 클록 단위로 측정한 응용 프로그램의 총 실행 시간이다.

  첫 번째 매크로를 사용하는 경우 현재 클록 값으로 평가되도록 정의되어야 한다. 두 번째 매크로를 사용하는 경우 'Time' 매개변수를 현재 클록 값으로 설정하도록 정의되어야 한다.


<a id="1254-the-uxtaskgetsystemstate-api-function"></a>
### 12.5.4 uxTaskGetSystemState() API 함수 (The uxTaskGetSystemState() API Function)

`uxTaskGetSystemState()`는 FreeRTOS 스케줄러의 제어를 받는 각 태스크의 상태 정보에 대한 스냅샷을 제공한다. 정보는 각 태스크당 하나의 인덱스를 갖는 `TaskStatus_t` 구조체 배열로 제공된다. `TaskStatus_t`는 Listing 12.5 및 아래 목록에 설명되어 있다.


<a name="list12.4" title="Listing 12.4 The uxTaskGetSystemState() API function prototype"></a>

```c
UBaseType_t uxTaskGetSystemState( TaskStatus_t * const pxTaskStatusArray,
                                  const UBaseType_t uxArraySize,
                                  configRUN_TIME_COUNTER_TYPE * const pulTotalRunTime );
```
***Listing 12.4*** *The uxTaskGetSystemState() API function prototype*

> 참고: `configRUN_TIME_COUNTER_TYPE`은 하위 호환성을 위해 기본적으로 `uint32_t`로 지정되지만, `uint32_t`가 너무 제한적인 경우 FreeRTOSConfig.h에서 오버라이드할 수 있다.


**uxTaskGetSystemState() 매개변수 및 반환 값**

- `pxTaskStatusArray`

  `TaskStatus_t` 구조체 배열을 가리키는 포인터이다.

  배열은 각 태스크당 최소 하나의 `TaskStatus_t` 구조체를 포함해야 한다. 태스크 수는 `uxTaskGetNumberOfTasks()` API 함수를 사용하여 확인할 수 있다.

  `TaskStatus_t` 구조체는 Listing 12.5에 나와 있으며, 구조체 멤버들은 다음 목록에 설명되어 있다.

- `uxArraySize`

  `pxTaskStatusArray` 매개변수가 가리키는 배열의 크기이다. 크기는 배열의 바이트 수가 아니라 배열에 포함된 인덱스 수(`TaskStatus_t` 구조체 수)로 지정된다.

- `pulTotalRunTime`

  `FreeRTOSConfig.h`에서 `configGENERATE_RUN_TIME_STATS`가 1로 설정된 경우, `*pulTotalRunTime`은 `uxTaskGetSystemState()`에 의해 타깃이 부팅된 이후의 총 실행 시간(응용 프로그램이 제공하는 런타임 통계 클록으로 정의됨)으로 설정된다.

  `pulTotalRunTime`은 선택 사항이며 총 실행 시간이 필요하지 않은 경우 NULL로 설정할 수 있다.

- 반환 값 (Return value)

  `uxTaskGetSystemState()`에 의해 채워진 `TaskStatus_t` 구조체의 수가 반환된다.

  반환된 값은 `uxTaskGetNumberOfTasks()` API 함수가 반환한 수와 같아야 하지만, `uxArraySize` 매개변수로 전달된 값이 너무 작으면 0이 된다.


<a name="list12.5" title="Listing 12.5 The TaskStatus\_t structure"></a>

```c
typedef struct xTASK_STATUS
{
    TaskHandle_t xHandle;
    const char *pcTaskName;
    UBaseType_t xTaskNumber;
    eTaskState eCurrentState;
    UBaseType_t uxCurrentPriority;
    UBaseType_t uxBasePriority;
    configRUN_TIME_COUNTER_TYPE ulRunTimeCounter;
    StackType_t * pxStackBase;

        StackType_t * pxEndOfStack;
```

**TaskStatus_t 구조체 멤버**

- `xHandle`

  구조체 내의 정보와 관련된 태스크의 핸들이다.

- `pcTaskName`

  사람이 읽을 수 있는 태스크의 텍스트 이름이다.

- `xTaskNumber`

  각 태스크는 고유한 `xTaskNumber` 값을 갖는다.

  응용 프로그램이 런타임에 태스크를 생성하고 삭제하는 경우, 새로 생성된 태스크가 이전에 삭제된 태스크와 동일한 핸들을 가질 수 있다. `xTaskNumber`는 응용 프로그램 코드와 커널 인식 디버거가 여전히 유효한 태스크와 동일한 핸들을 가졌던 삭제된 태스크를 구별할 수 있도록 제공된다.

- `eCurrentState`

  태스크의 상태를 유지하는 열거형 타입이다. `eCurrentState`는 다음 값 중 하나를 가질 수 있다:
  
  - `eRunning`
  - `eReady`
  - `eBlocked`
  - `eSuspended`
  - `eDeleted`

  태스크는 `vTaskDelete()` 호출로 삭제된 시점부터 유휴 태스크가 삭제된 태스크의 내부 데이터 구조 및 스택에 할당된 메모리를 해제할 때까지의 짧은 기간 동안에만 `eDeleted` 상태로 보고된다. 그 이후에는 태스크가 더 이상 어떤 형태로도 존재하지 않으므로 핸들을 사용하려고 시도하는 것은 유효하지 않다.

- `uxCurrentPriority`

  `uxTaskGetSystemState()`가 호출되었을 당시 태스크가 실행 중이던 우선순위이다. `uxCurrentPriority`는 [8.3 뮤텍스 (및 바이너리 세마포어)](ch08.md#83-mutexes-and-binary-semaphores) 절에 설명된 우선순위 상속 메커니즘에 따라 태스크에 일시적으로 더 높은 우선순위가 할당된 경우에만 응용 프로그램 작성자가 태스크에 할당한 우선순위보다 높아진다.

- `uxBasePriority`

  응용 프로그램 작성자가 태스크에 할당한 기본 우선순위이다. `uxBasePriority`는 FreeRTOSConfig.h에서 `configUSE_MUTEXES`가 1로 설정된 경우에만 유효하다.

- `ulRunTimeCounter`

  태스크가 생성된 이후 태스크가 사용한 총 실행 시간이다. 총 실행 시간은 런타임 통계 수집을 위해 응용 프로그램 작성자가 제공한 클록을 사용하는 절대 시간으로 제공된다. `ulRunTimeCounter`는 FreeRTOSConfig.h에서 `configGENERATE_RUN_TIME_STATS`가 1로 설정된 경우에만 유효하다.
  
- `pxStackBase`

  이 태스크에 할당된 스택 영역의 기본(base) 주소를 가리킨다.

- `pxTopOfStack`

  이 태스크에 할당된 스택 영역의 현재 상단(top) 주소를 가리킨다. `pxTopOfStack` 필드는 스택이 상향 성장하거나(`portSTACK_GROWTH`가 0보다 큼) FreeRTOSConfig.h에서 `configRECORD_STACK_HIGH_ADDRESS`가 1로 설정된 경우에만 유효하다.

- `pxEndOfStack`

  이 태스크에 할당된 스택 영역의 끝(end) 주소를 가리킨다. `pxEndOfStack` 필드는 스택이 상향 성장하거나(`portSTACK_GROWTH`가 0보다 큼) FreeRTOSConfig.h에서 `configRECORD_STACK_HIGH_ADDRESS`가 1로 설정된 경우에만 유효하다.

- `usStackHighWaterMark`

  태스크의 스택 고수위(high water mark)이다. 이는 태스크가 생성된 이후 태스크에 남아 있던 최소 스택 공간의 양이다. 태스크가 스택 오버플로에 얼마나 근접했는지를 나타내는 지표이며, 이 값이 0에 가까울수록 스택 오버플로에 근접했음을 의미한다. `usStackHighWaterMark`는 바이트 단위로 지정된다.
  
- `uxCoreAffinityMask`

  태스크가 실행될 수 있는 코어를 나타내는 비트 단위 값이다. 코어 번호는 0부터 `configNUMBER_OF_CORES` - 1까지 매겨진다. 예를 들어 코어 0과 코어 1에서 실행될 수 있는 태스크는 `uxCoreAffinityMask`가 0x03으로 설정된다. `uxCoreAffinityMask` 필드는 FreeRTOSConfig.h에서 `configUSE_CORE_AFFINITY`가 1로 설정되고 `configNUMBER_OF_CORES`가 1보다 크게 설정된 경우에만 사용할 수 있다.

### 12.5.7 런타임 통계 생성 및 표시 실습 예제 (Generating and Displaying Run-Time Statistics, a Worked Example)

이 예제에서는 가상의 16비트 타이머를 사용하여 32비트 런타임 통계 클록을 생성한다. 카운터는 16비트 값이 최대값에 도달할 때마다 인터럽트를 발생시키도록 구성되어 사실상 오버플로 인터럽트를 생성한다. 인터럽트 서비스 루틴은 오버플로 발생 횟수를 센다.

32비트 값은 오버플로 발생 카운트를 32비트 값의 상위 2바이트로 사용하고, 현재 16비트 카운터 값을 32비트 값의 하위 2바이트로 사용하여 생성된다. 인터럽트 서비스 루틴에 대한 의사 코드는 Listing 12.10에 나와 있다.


<a name="list12.10" title="Listing 12.10 16-bit timer overflow interrupt handler used to count timer overflows"></a>

```c
void TimerOverflowInterruptHandler( void )
{
    /* Just count the number of interrupts. */
    ulOverflowCount++;

    /* Clear the interrupt. */
    ClearTimerInterrupt();
}
```
***Listing 12.10*** *16-bit timer overflow interrupt handler used to count timer overflows*

Listing 12.11은 런타임 통계 수집을 활성화하기 위해 FreeRTOSConfig.h에 추가된 라인들을 보여준다.


<a name="list12.11" title="Listing 12.11 Macros added to FreeRTOSConfig.h to enable the collection of run-time statistics"></a>

```c
/* Set configGENERATE_RUN_TIME_STATS to 1 to enable collection of run-time 
   statistics. When this is done, both portCONFIGURE_TIMER_FOR_RUN_TIME_STATS()
   and portGET_RUN_TIME_COUNTER_VALUE() or 
   portALT_GET_RUN_TIME_COUNTER_VALUE(x) must also be defined. */
#define configGENERATE_RUN_TIME_STATS 1

/* portCONFIGURE_TIMER_FOR_RUN_TIME_STATS() is defined to call the function 
   that sets up the hypothetical 16-bit timer (the function's implementation 
   is not shown). */
void vSetupTimerForRunTimeStats( void );
#define portCONFIGURE_TIMER_FOR_RUN_TIME_STATS()  vSetupTimerForRunTimeStats()

/* portALT_GET_RUN_TIME_COUNTER_VALUE() is defined to set its parameter to the
   current run-time counter/time value. The returned time value is 32-bits 
   long, and is formed by shifting the count of 16-bit timer overflows into 
   the top two bytes of a 32-bit number, then bitwise ORing the result with 
   the current 16-bit counter value. */
#define portALT_GET_RUN_TIME_COUNTER_VALUE( ulCountValue )                  \
{                                                                           \
    extern volatile unsigned long ulOverflowCount;                          \
                                                                            \
    /* Disconnect the clock from the counter so it does not change          \
       while its value is being used. */                                    \
    PauseTimer();                                                           \
                                                                            \
    /* The number of overflows is shifted into the most significant         \
       two bytes of the returned 32-bit value. */                           \
    ulCountValue = ( ulOverflowCount << 16UL );                             \
                                                                            \
    /* The current counter value is used as the two least significant       \
       bytes of the returned 32-bit value. */                               \
    ulCountValue |= ( unsigned long ) ReadTimerCount();                     \
                                                                            \
    /* Reconnect the clock to the counter. */                               \
    ResumeTimer();                                                          \
}
```
***Listing 12.11*** *Macros added to FreeRTOSConfig.h to enable the collection of run-time statistics*

Listing 12.12에 표시된 태스크는 수집된 런타임 통계를 5초마다 출력한다.


<a name="list12.12" title="Listing 12.12 The task that prints out the collected run-time statistics"></a>

```c
#define RUN_TIME_STATS_STRING_BUFFER_LENGTH       512

/* For clarity, calls to fflush() have been omitted from this code listing. */
static void prvStatsTask( void *pvParameters )
{
    TickType_t xLastExecutionTime;

    /* The buffer used to hold the formatted run-time statistics text needs to
       be quite large. It is therefore declared static to ensure it is not
       allocated on the task stack. This makes this function non re-entrant. */
    static signed char cStringBuffer[ RUN_TIME_STATS_STRING_BUFFER_LENGTH ];

    /* The task will run every 5 seconds. */
    const TickType_t xBlockPeriod = pdMS_TO_TICKS( 5000 );

    /* Initialize xLastExecutionTime to the current time. This is the only
       time this variable needs to be written to explicitly. Afterwards it is 
       updated internally within the vTaskDelayUntil() API function. */
    xLastExecutionTime = xTaskGetTickCount();

    /* As per most tasks, this task is implemented in an infinite loop. */
    for( ;; )
    {
        /* Wait until it is time to run this task again. */
        xTaskDelayUntil( &xLastExecutionTime, xBlockPeriod );

        /* Generate a text table from the run-time stats. This must fit into
           the cStringBuffer array. */
        vTaskGetRunTimeStatistics( cStringBuffer, RUN_TIME_STATS_STRING_BUFFER_LENGTH );

        /* Print out column headings for the run-time stats table. */
        printf( "\nTask\t\tAbs\t\t\t%%\n" );
        printf( "-------------------------------------------------------------\n" );

        /* Print out the run-time stats themselves. The table of data contains
           multiple lines, so the vPrintMultipleLines() function is called 
           instead of calling printf() directly. vPrintMultipleLines() simply 
           calls printf() on each line individually, to ensure the line 
           buffering works as expected. */ 
        vPrintMultipleLines( cStringBuffer );
    }
}
```
***Listing 12.12*** *The task that prints out the collected run-time statistics*

## 12.6 트레이스 훅 매크로 (Trace Hook Macros)

트레이스 매크로는 FreeRTOS 소스 코드 내의 핵심 위치에 배치된 매크로들이다. 기본적으로 이 매크로들은 비어 있으므로 코드를 전혀 생성하지 않으며 런타임 오버헤드도 없다. 기본 빈 구현을 오버라이드함으로써 응용 프로그램 개발자는 다음을 수행할 수 있다:

- FreeRTOS 소스 파일을 수정하지 않고도 FreeRTOS 내부에 코드를 삽입한다.

- 타깃 하드웨어에서 사용 가능한 모든 수단을 통해 상세한 실행 순서 정보를 출력한다. 트레이스 매크로는 FreeRTOS 소스 코드의 충분한 위치에 나타나므로 완전하고 상세한 스케줄러 활동 트레이스 및 프로파일링 로그를 생성하는 데 사용할 수 있다.


<a id="1261-available-trace-hook-macros"></a>
### 12.6.1 사용 가능한 트레이스 훅 매크로 (Available Trace Hook Macros)

모든 매크로를 여기에 자세히 설명하기에는 공간이 너무 많이 소요된다. 아래 목록은 응용 프로그램 작성자에게 가장 유용하다고 판단되는 매크로들의 하위 집합을 상세히 설명한다.

아래 목록의 설명 중 상당수는 `pxCurrentTCB`라는 변수를 언급한다. `pxCurrentTCB`는 Running 상태에 있는 태스크의 핸들을 유지하는 FreeRTOS 비공개(private) 변수이며, `FreeRTOS/Source/tasks.c` 소스 파일에서 호출되는 모든 매크로에서 사용할 수 있다.

**가장 흔히 사용되는 주요 트레이스 훅 매크로 목록**

- `traceTASK_INCREMENT_TICK(xTickCount)`

  틱 인터럽트 도중 틱 카운트가 증가하기 전에 호출된다. `xTickCount` 매개변수는 새로운 틱 카운트 값을 매크로로 전달한다.

- `traceTASK_SWITCHED_OUT()`

  새로운 태스크가 실행되도록 선택되기 전에 호출된다. 이 시점에서 `pxCurrentTCB`에는 Running 상태를 떠나려는 태스크의 핸들이 포함되어 있다.

- `traceTASK_SWITCHED_IN()`

  태스크가 실행되도록 선택된 후에 호출된다. 이 시점에서 `pxCurrentTCB`에는 Running 상태로 진입하려는 태스크의 핸들이 포함되어 있다.

- `traceBLOCKING_ON_QUEUE_RECEIVE(pxQueue)`
  
  빈 큐에서 읽기를 시도하거나 빈 세마포어 또는 뮤텍스를 '획득(take)'하려 한 후 현재 실행 중인 태스크가 Blocked 상태로 진입하기 직전에 호출된다. `pxQueue` 매개변수는 대상 큐 또는 세마포어의 핸들을 매크로로 전달한다.

- `traceBLOCKING_ON_QUEUE_SEND(pxQueue)`
  
  가득 찬 큐에 쓰기를 시도한 후 현재 실행 중인 태스크가 Blocked 상태로 진입하기 직전에 호출된다. `pxQueue` 매개변수는 대상 큐의 핸들을 매크로로 전달한다.

- `traceQUEUE_SEND(pxQueue)`
  
  큐 전송 또는 세마포어 'give'가 성공했을 때 `xQueueSend()`, `xQueueSendToFront()`, `xQueueSendToBack()` 또는 모든 세마포어 'give' 함수 내부에서 호출된다. `pxQueue` 매개변수는 대상 큐 또는 세마포어의 핸들을 매크로로 전달한다.

- `traceQUEUE_SEND_FAILED(pxQueue)`

  큐 전송 또는 세마포어 'give' 작업이 실패했을 때 `xQueueSend()`, `xQueueSendToFront()`, `xQueueSendToBack()` 또는 모든 세마포어 'give' 함수 내부에서 호출된다. 큐가 가득 차 있고 지정된 블록 시간 동안 계속 가득 차 있는 경우 큐 전송 또는 세마포어 'give'가 실패한다. `pxQueue` 매개변수는 대상 큐 또는 세마포어의 핸들을 매크로로 전달한다.

- `traceQUEUE_RECEIVE(pxQueue)`

  큐 수신 또는 세마포어 'take'가 성공했을 때 `xQueueReceive()` 또는 모든 세마포어 'take' 함수 내부에서 호출된다. `pxQueue` 매개변수는 대상 큐 또는 세마포어의 핸들을 매크로로 전달한다.

- `traceQUEUE_RECEIVE_FAILED(pxQueue)`

  큐 또는 세마포어 수신 작업이 실패했을 때 `xQueueReceive()` 또는 모든 세마포어 'take' 함수 내부에서 호출된다. 큐나 세마포어가 비어 있고 지정된 블록 시간 동안 계속 비어 있는 경우 큐 수신 또는 세마포어 'take' 작업이 실패한다. `pxQueue` 매개변수는 대상 큐 또는 세마포어의 핸들을 매크로로 전달한다.

- `traceQUEUE_SEND_FROM_ISR(pxQueue)`

  전송 작업이 성공했을 때 `xQueueSendFromISR()` 내부에서 호출된다. `pxQueue` 매개변수는 대상 큐의 핸들을 매크로로 전달한다.

- `traceQUEUE_SEND_FROM_ISR_FAILED(pxQueue)`

  전송 작업이 실패했을 때 `xQueueSendFromISR()` 내부에서 호출된다. 큐가 이미 가득 찬 경우 전송 작업이 실패한다. `pxQueue` 매개변수는 대상 큐의 핸들을 매크로로 전달한다.

- `traceQUEUE_RECEIVE_FROM_ISR(pxQueue)`

  수신 작업이 성공했을 때 `xQueueReceiveFromISR()` 내부에서 호출된다. `pxQueue` 매개변수는 대상 큐의 핸들을 매크로로 전달한다.

- `traceQUEUE_RECEIVE_FROM_ISR_FAILED(pxQueue)`

  큐가 이미 비어 있어 수신 작업이 실패했을 때 `xQueueReceiveFromISR()` 내부에서 호출된다. `pxQueue` 매개변수는 대상 큐의 핸들을 매크로로 전달한다.

- `traceTASK_DELAY_UNTIL( xTimeToWake )`

  호출 태스크가 Blocked 상태로 진입하기 직전에 `xTaskDelayUntil()` 내부에서 호출된다.

- `traceTASK_DELAY()`

  호출 태스크가 Blocked 상태로 진입하기 직전에 `vTaskDelay()` 내부에서 호출된다.


<a id="1262-defining-trace-hook-macros"></a>
### 12.6.2 트레이스 훅 매크로 정의 (Defining Trace Hook Macros)

각 트레이스 매크로에는 기본 빈 정의가 있다. FreeRTOSConfig.h에 새로운 매크로 정의를 제공하여 기본 정의를 오버라이드할 수 있다. 트레이스 매크로 정의가 길어지거나 복잡해지면 새로운 헤더 파일에 구현한 다음 해당 헤더 파일을 FreeRTOSConfig.h에서 포함시킬 수 있다.

소프트웨어 엔지니어링 모범 사례에 따라 FreeRTOS는 엄격한 데이터 은닉 정책을 유지한다. 트레이스 매크로를 사용하면 사용자 코드를 FreeRTOS 소스 파일에 추가할 수 있으므로, 트레이스 매크로에 보이는 데이터 타입은 응용 프로그램 코드에 보이는 데이터 타입과 다르다:

- `FreeRTOS/Source/tasks.c` 소스 파일 내부에서 태스크 핸들은 태스크를 설명하는 데이터 구조체(태스크의 *태스크 제어 블록(Task Control Block)*, 즉 *TCB*)를 가리키는 포인터이다. `FreeRTOS/Source/tasks.c` 소스 파일 외부에서 태스크 핸들은 `void`를 가리키는 포인터이다.

- `FreeRTOS/Source/queue.c` 소스 파일 내부에서 큐 핸들은 큐를 설명하는 데이터 구조체를 가리키는 포인터이다. `FreeRTOS/Source/queue.c` 소스 파일 외부에서 큐 핸들은 `void`를 가리키는 포인터이다.

> *FreeRTOS 버전 간에 비공개 데이터 구조가 변경될 수 있으므로 트레이스 매크로에서 일반적으로 비공개인 FreeRTOS 데이터 구조체에 직접 접근하는 경우 극도의 주의가 필요하다.*
