# FreeRTOS Kernel Book 한국어판 번역 지침

버전: v0.3 · 갱신일: 2026-11-01

상태: 한국어 본문·그림 통합본과 이후 교정에 적용하는 기준본. 현재 검수 범위는 REVIEW.md에 기록한다.

기준 원문: [FreeRTOS-Kernel-Book](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/tree/ba20b2f820926587d5ee20ce312b3789d63f795c), commit `ba20b2f820926587d5ee20ce312b3789d63f795c`

함께 읽을 문서: [한국어 자료 조사](RESEARCH.md), [용어집](GLOSSARY.md)

## 1. 번역의 범위와 기준

이 지침은 공식 Kernel Book을 한국어로 옮길 때 적용한다. 원문의 장·절 구성과 설명의 깊이를 유지한다. 강의용 축약, 독자 수준 변경, STM32 전용 예제 변환은 별도 편집 작업으로 구분한다. 기존 영어 슬라이드와 `_ko` 강의·실습 자료는 이 작업의 수정 대상에 포함하지 않는다.

의미 판단은 고정한 영문 원문을 기준으로 한다. 현재 API 문서나 코드와 차이가 발견되면 원문의 버전 맥락을 먼저 확인하고, 변경 사항은 `[옮긴이 주]`나 정오 기록에 분리한다. 다른 사람의 번역·해설은 용어와 설명 방법의 비교 자료로 사용한다.

상위 FreeRTOS 강의 프로젝트에서 정한 영문 객체명·식별자 보존 원칙을 이 문서에 반영했다. 이 저장소만으로 작업할 수 있도록 필요한 규칙을 여기에 담는다. 아래의 표기 선택은 이 한국어판의 기준이며 국가 표준이나 FreeRTOS 공식 번역 표준을 의미하지 않는다.

## 2. 영어 유지와 한국어 병기

| 구분 | 표기 원칙 | 예 |
| --- | --- | --- |
| 제품·규격·도구 이름 | 공식 철자와 대소문자 유지 | FreeRTOS, Arm Cortex-M, GCC, STM32CubeIDE |
| API·매크로·형·변수·경로 | 원문 문자열 유지, 본문에서는 코드 서식 | `xTaskCreate()`, `TickType_t`, `configUSE_PREEMPTION`, `FreeRTOSConfig.h` |
| FreeRTOS 객체와 주요 구성요소 | 영어 유지, 장의 첫 등장에 한국어 풀이 | task(태스크), queue(큐), mutex(뮤텍스), scheduler(스케줄러) |
| 공식 상태 이름 | 영문 대문자 유지, 한국어 설명 병기 | Ready 상태(실행 가능), Blocked 상태(이벤트 또는 시간 대기) |
| 일반 운영체제 개념 | 용어집의 한국어 대표 표현, 장의 첫 등장에 영어 병기 | 우선순위 역전(priority inversion), 상호 배제(mutual exclusion) |
| 일반 동작 | 자연스러운 한국어 동사 | 생성한다, 호출한다, 반환한다, 대기한다, 복사한다 |

객체·개념명은 일반 글꼴을 사용하고, 실제 코드 식별자에 코드 서식을 적용한다. 문장 시작이라고 task를 임의로 `Task`로 바꾸지 않는다. 원문의 `Task 1`처럼 예제의 이름으로 쓰인 표기는 유지한다.

첫 병기는 각 장에서 한 번 한다. 독립적으로 배포하는 절은 그 절의 첫 등장에서도 병기할 수 있다. 이후 문장마다 괄호를 반복하지 않는다. 영어 복수형은 자연어 문장에서 단수 기본형으로 적는다. 예: ‘두 tasks’ → ‘task 두 개’. 코드·로그 속 문자열은 그대로 둔다.

영문 뒤의 조사는 붙인다. 예: ‘task는’, ‘queue에’, ‘`xTaskCreate()`를 호출한다’. 독음이 모호하면 ‘`configUSE_PREEMPTION`의 값’처럼 문장 구조를 바꾼다. ‘을(를)’, ‘은(는)’ 같은 자동번역 잔재를 남기지 않는다.

## 3. 문체와 문장 구성

본문은 평서형 ‘한다/이다’체, 절차는 ‘설정한다/실행한다/확인한다’체로 통일한다. 원문에 없는 독자 호명, 감탄, 대화, 난이도 평가를 추가하지 않는다. 제목은 사용자 선택에 따라 `한국어 (영어 원제)`로 병기하고 번호는 원문대로 유지한다. 예: `4 태스크 관리 (Task Management)`. 제목·목차의 한국어 표제는 검색과 탐색을 위한 예외이며, 본문 객체명은 영어 유지 원칙을 따른다. 동일한 각주를 양쪽 제목에서 중복 호출하지 않는다.

한 문장은 가능한 한 하나의 중심 판단을 담는다. 긴 영어 문장을 나눌 때 조건과 예외가 어느 동작에 적용되는지 분명히 한다. 원문의 불릿·표가 병렬 조건을 나타내면 구조를 유지한다. 문체를 정리한다는 이유로 기술적 부정이나 반복된 제한 조건을 삭제하지 않는다.

행위 주체를 알 수 있으면 드러낸다. ‘함수가 사용되어진다’보다 ‘이 함수를 호출한다’처럼 쓴다. 반대로 원문이 주체를 특정하지 않으면 주체를 추정해 추가하지 않는다. 자연스러운 피동문까지 일괄적으로 능동문으로 바꾸지 않는다.

| 원문의 표현·관계 | 한국어 처리 |
| --- | --- |
| must / must not | ‘해야 한다 / 해서는 안 된다’로 의무·금지 유지 |
| should | 권장 문맥이면 ‘권장한다’. 기술적 기대·추론이면 해당 문맥에 맞게 옮긴다 |
| can / may | 기능·가능·허용을 문맥으로 구분. 가능성을 확정 사실로 바꾸지 않는다 |
| only if / if / unless | 필요조건·조건·예외를 구분. ‘경우에만’의 범위를 보존한다 |
| at least / at most / up to | ‘이상 / 이하 / 최대’의 경계 포함 여부를 보존한다 |
| higher / highest | 비교급과 최상급을 구분. ‘높은’과 ‘가장 높은’을 바꾸지 않는다 |
| respectively / either / both | 대응 순서·선택·동시 조건을 보존한다 |
| will / may / typically | 동작 보장·가능성·통상적 동작의 강도를 구분한다 |

자연스러운 한국어와 원문의 의미 보존을 함께 지킨다. 문체상의 긍정형 선호보다 원문의 금지·부정·예외와 기술 의미를 우선한다. 쉬운 동사를 불필요하게 어려운 한자어로 바꾸지 않는다.

## 4. 기술적 의미 보존

다음은 원문 대조 때 집중해서 볼 항목이다. 각 문장의 정확한 조건은 해당 절과 API 설명에서 확인한다.

| 검토 항목 | 기준 |
| --- | --- |
| 상태와 동작 | Ready 전환과 실제 Running 진입을 구분한다. unblock을 곧바로 ‘실행한다’로 옮기지 않는다 |
| 대기와 실행 중단 | Blocked, Suspended, busy wait, scheduler suspension을 각각 구분한다 |
| 호출 주체 | task 문맥과 ISR 문맥을 유지한다. `FromISR`을 일반 API로 바꾸지 않는다 |
| 시간 | tick과 ms를 구분한다. 주어진 tick rate를 보존한다. 지연 후 Ready가 되는 시각과 실제 실행 시각을 구분한다 |
| 무기한 대기 | `portMAX_DELAY`가 무기한 대기를 뜻하는 API·설정 조건을 함께 옮긴다. 0과 혼동하지 않는다 |
| 우선순위 | task 우선순위와 하드웨어 interrupt 우선순위의 숫자 방향을 원문 맥락에서 확인한다 |
| 데이터 복사 | queue가 복사하는 항목과 포인터가 가리키는 데이터를 구분한다 |
| 메모리 단위 | bit, byte, word, `StackType_t` 단위를 보존한다. stack depth를 무조건 바이트 수로 바꾸지 않는다 |
| 동기화 | mutex의 소유·반납과 semaphore의 신호·계수를 문맥에 맞게 구분한다 |
| 단일·다중 코어 | ‘한 번에 task 하나 실행’ 같은 설명의 코어 수 전제를 유지한다 |
| 설정·버전 | `config...`, `INCLUDE_...`, port별 조건과 원문의 API 버전을 함께 보존한다 |

핵심 근거: [4장 Task Management](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/ba20b2f820926587d5ee20ce312b3789d63f795c/ch04.md), [5장 Queue Management](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/ba20b2f820926587d5ee20ce312b3789d63f795c/ch05.md), [7장 Interrupt Management](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/ba20b2f820926587d5ee20ce312b3789d63f795c/ch07.md), [8장 Resource Management](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/ba20b2f820926587d5ee20ce312b3789d63f795c/ch08.md).

## 5. 코드·수치·그림·링크

- fenced code block, 들여쓰기 코드, HTML의 `pre`·`code` 내부는 주석·문자열·공백을 포함해 원문 그대로 유지한다. 주석의 한국어 설명이 필요하면 코드 아래에 별도로 적는다.
- 함수명·반환값·매개변수·매크로·파일명·경로·명령·로그는 보호한다. 자연어 설명을 담은 inline code는 식별자인지 먼저 판별한다.
- 수치·단위·공식·연산자·진수·접미사와 예제의 우선순위 값을 유지한다. `32-bit` → ‘32비트’는 가능하지만 ‘32바이트’는 의미 변경이다.
- 장·절·그림·표·코드·예제 번호를 유지한다. 표기는 Figure → ‘그림’, Table → ‘표’, Listing → ‘코드’, Example → ‘예제’로 통일한다. 공식 문서 제목을 인용할 때는 원제도 남긴다.
- 삽입 그림의 설명 문구도 한국어로 옮긴다. Codex에서 원본을 확인하고 `ko/assets/`에 한글화한 파생 asset을 준비한다. 영문 원본 `media/`는 보존한다. 용어집의 객체명·상태명, API·코드·로그·수치·단위는 유지하고 도형·화살표·시간 순서·색상 의미를 대조한다.
- 실행 로그·실제 도구 화면·로고·숫자 전용 그림은 원본을 보존하고 한국어 caption·설명으로 읽기를 돕는다. 실제 영문 UI를 한글 제품 화면처럼 바꾸지 않는다. caption과 대체 텍스트도 한국어로 작성한다.
- 그림의 원본–파생 경로·hash·사용 위치·번역 지시문·검수 결과는 `ko/assets/manifest.json`에 기록한다. 검수된 asset만 번역 초안에 사용하며 생성 성공을 검수 완료로 간주하지 않는다.
- 기존 HTML `id`·`name`·anchor, 수식, Markdown 링크 목적지와 표의 행·열 대응을 보존한다. 한국어 제목 때문에 자동 anchor가 달라지면 영문 원본 anchor를 명시적으로 추가한다.
- `ko/` 아래 파일에서는 이미지 경로가 `../media/...` 등으로 달라질 수 있다. 링크 목적지 변경은 경로 조정으로 기록하고, 연결된 파일과 anchor가 실제로 존재하는지 검사한다. 단순 정규식 치환 결과만으로 통과 처리하지 않는다.
- 원문에서 깨진 링크·잘못된 식별자·번호 중복을 발견하면 정오 항목에 원문 위치와 근거를 기록한다. 본문을 조용히 수정해 원문과의 차이를 숨기지 않는다.

## 6. 편집 예시

아래는 지침을 설명하기 위해 작성한 예시다. 책이나 블로그의 문장을 직접 인용한 번역 표본은 아니다.

| 피할 문장 | 이 지침에 따른 문장 | 확인할 의미 |
| --- | --- | --- |
| 태스크는 블록된 상태로 놓여지게 된다 | task는 Blocked 상태로 전환된다 | 불필요한 이중 피동 제거 |
| 큐가 비면 태스크가 깨어나 실행된다 | queue에서 데이터가 제공되면 대기하던 task는 Ready 상태로 전환될 수 있다 | 데이터 조건과 Ready/Running 구분 |
| 이 함수는 ISR에서 호출하는 것을 피하는 게 좋다 | 이 함수는 ISR에서 호출해서는 안 된다 | 원문이 금지한 경우의 강도 보존 |
| queue는 포인터가 가리키는 데이터를 복사한다 | queue 항목이 포인터이면 포인터 값을 복사한다 | 복사 대상 구분 |
| task를 100 tick 동안 정지한다, 즉 100 ms다 | task를 100 tick 동안 지연한다 | tick rate 없이 시간 환산 금지 |
| 우선순위 상속이 역전을 완전히 해결한다 | 우선순위 상속은 우선순위 역전의 영향을 줄인다 | 원문의 효과 범위 보존 |
| 우리는 이제 queue에 대해 알아볼 것이다 | 이 절에서는 queue의 동작을 설명한다 | 불필요한 화자·미래형 정리 |

문장 예시는 문맥에 따라 적용한다. 예를 들어 첫 문장이 조건절의 일부이면 그 조건까지 함께 보존한다.

## 7. 번역 저장소 구성

공식 저장소를 직접 clone한 로컬 저장소다. 현재 생성된 준비 파일과 추후 만들 번역 파일을 구분한다.

```text
FreeRTOS-Kernel-Book-ko/
  README.md, ch01.md ... ch13.md  # upstream 영어 원본, 변경하지 않음
  toc.md, media/, examples/      # upstream 원본과 예제
  LICENSE*                      # 원문 고지 보존
  README.ko.md                   # 한국어판 작업 안내
  AGENTS.md                      # 후속 작업의 필수 규칙
  PROJECT_STATE.md               # 현재 상태와 다음 시작점
  ko/
    STYLE_GUIDE.md               # 번역 지침 기준본
    GLOSSARY.md                  # 용어집 기준본
    RESEARCH.md                  # 2026-11-01 조사 기록
    WORKFLOW.md                  # 별도 번역 작업 절차·요청 양식
    translation-manifest.json    # 고정 원문·파일별 상태
    assets/                      # 한국어 그림·원본 대응·검수 상태
```

본문 13장과 부속 문서 5종은 `ko/chNN.md`, `ko/toc.md`, `ko/booktitle.md` 등 원문 대응 경로에 있다. 후속 변경은 지정 범위에만 적용하며 부분 검토를 장 전체의 검토 완료로 기록하지 않는다.

영문 원격 이름은 `upstream`이고 한국어판 정본은 `origin/main`이다. 영문 기준선은 manifest와 `upstream-baseline`에 보존한다. 후속 작업 branch는 한국어판 정본에서 만든다. 예제 submodule과 중첩 submodule은 초기화했으며 예제 빌드·실행은 검증하지 않았다.

지침과 용어집의 현재 기준본은 이 저장소의 `ko/` 아래 파일이다. 상위 프로젝트 `index/`의 v0.1 문서는 사전 준비 기록으로 보존하며 독립적으로 갱신하지 않는다. 기존 수집 `raw/`, 웹북, 강의·실습 자료는 별도 자료로 보존한다. HTML·PDF 등 배포 형식은 후속 지시에 따라 정한다.

## 8. 파일별 기록과 검수

각 번역 파일에는 독자에게 필요한 번역 상태를 간결히 표시하고, 작업 기록에는 다음 정보를 둔다.

```yaml
upstream_repository: https://github.com/FreeRTOS/FreeRTOS-Kernel-Book
upstream_commit: ba20b2f820926587d5ee20ce312b3789d63f795c
source_path: ch04.md
source_blob_sha: <해당 파일의 Git blob SHA>
translation_path: ko/ch04.md
style_version: 0.3
glossary_version: 0.3
status: draft
translated_at: <실제 번역 날짜>
reviewed_by: <실제 검토자 또는 미검토>
```

`not-started → draft → source-checked → language-reviewed → release-ready` 순서로 상태를 기록한다. 단계는 미착수, 번역 생성, 원문 대조, 한국어 검토, 배포 요건 확인을 뜻한다. 자동 검사만으로 사람이 검토했다고 표시하지 않는다. 미해결 항목에는 `check-against-source` 또는 `needs-human-check`와 정확한 위치를 남긴다.

장별 완료 조건은 다음과 같다.

1. 제목 계층, 문단·불릿·표·그림·예제 대응을 확인하고 누락·임의 요약이 없는지 대조한다.
2. 코드 블록을 원문과 비교하고, API·매크로·형·변수·경로·수치·단위·연산자를 검사한다. 단순 개수 비교를 넘어 실제 문자열과 문맥을 확인한다.
3. 필수 조건·예외·부정·비교급·시점·주체를 문장 단위로 확인한다. 기술 조건이 바뀐 항목은 0건이어야 한다.
4. 용어집의 대표 표기, 첫 병기, 상태 이름, ‘한다’체를 검토한다. `__TK...__`, 미해결 자리표시자, ‘을(를)’ 같은 잔재를 확인한다.
5. Markdown 링크·HTML anchor·이미지 경로·caption·목차를 검사한다. 제목 번역에 따른 anchor 변화를 포함한다.
6. 실제 Markdown 렌더링에서 표·그림·코드·한글 표시를 읽는다. PDF를 만들면 페이지 수·글꼴·잘림을 별도로 확인한다.
7. 원저자·원문·라이선스·기준 commit·변경 사실·비공식 번역 표시가 있는지 확인한다. 미해결 사항이 남으면 배포 준비 완료로 표시하지 않는다.

자동 검사 통과는 의미 검토를 대신하지 않는다. 별도 번역 요청에서 범위가 지정되지 않았다면 초기 표본 후보는 4.7절의 상태 설명과 5.3절의 매개변수·반환값 설명이다. 준비 작업만으로 이 절의 번역을 시작하지 않는다. 두 절은 문체와 기술 조건 보존을 함께 검토하기에 적합하다.

## 9. 번역 작업용 공통 지시문

```text
제공한 FreeRTOS Kernel Book의 지정 절을 한국어로 번역한다.
입력된 영문 원문, 기준 commit, STYLE_GUIDE, GLOSSARY를 따른다.

1. 원문 정보, 구조, 조건, 예외, 부정, 숫자, 단위, 예제 번호를 보존한다.
2. task, queue, mutex 등 지정 객체명과 공식 상태명은 영어로 유지한다.
   해당 장의 첫 등장에 용어집의 한국어 풀이를 병기한다.
3. API, 매크로, 형, 변수, 파일명, 경로, 명령, 로그, 코드 블록은 유지한다.
   코드 주석의 설명은 코드 밖에 별도로 적는다.
4. 본문은 자연스러운 한다체로 작성한다. 원문을 임의로 축약하지 않는다.
5. 원문 밖의 설명은 옮긴이 주로 구분하고 근거를 붙인다.
6. Ready와 Running, Blocked와 Suspended, tick과 ms를 구분한다.
7. 원문의 오류 의심 사항은 조용히 고치지 말고 위치·근거를 보고한다.
8. 출력은 번역 Markdown과 별도의 검토 필요 목록으로 구성한다.
   불확실한 내용은 check-against-source로 표시한다.
```

장별 작업에 앞서 대상 범위, 이미 병기한 용어, 앞뒤 문단을 함께 제공한다. 단어 치환표만으로 전체 파일을 자동번역하지 않는다.

## 10. 공개 정본의 관리

한국어판 `origin/main`을 기준으로 변경하고 작업 branch에서 검수 후 PR을 제출한다. 공개 여부는 검수 단계와 별개다. 공개됐다는 이유로 manifest를 `release-ready`로 올리지 않는다. 원문 오기와 번역 수정은 [원문 대조 사항](SOURCE_NOTES.md)에 기록한다. 원문 README는 `README.upstream.md`에 보존하며 루트 README는 비공식 한국어판 안내로 사용한다.
